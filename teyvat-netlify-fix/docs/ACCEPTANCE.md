## 构建与依赖

`npm run build` 与 `npx --offline netlify-cli build --offline` 已通过，生成 React 生产资源并打包全部 5 个 Netlify 函数。

`node scripts/verify-netlify.mjs`：解压实际 Netlify 函数 ZIP，在隔离工作目录中运行现代 Request/Response 入口的 API、JSON 初始化、SEO 页面和后台 DOCX 导入；检查全部 5 个函数使用 runtime API 2。验证迁移 SQL、页面模板、解析线程与解析依赖定位，解析结果重新打开数据库后仍保留。该检查不连接或部署云端。

2026-10-12 Netlify 修复：旧入口不能自动取得 Netlify Database 连接；已改用现代运行时及官方兼容包装器。另升级 serverless-http 至 4，解决旧适配器让 Express JSON 请求体保持 Buffer 的问题。新增 `tests/netlify-runtime.test.mjs` 使用真实 Netlify Database SDK + pg 驱动，通过 TCP 连接独立 PGlite 测试引擎；验证缺少连接、连接拒绝后恢复、角色查询、平台初始化密钥、JSON 初始化及会话 Cookie。此测试覆盖连接方式，但不能替代生产账号的函数日志与线上验证。

`npm audit --omit=dev --audit-level=high` 无 high/critical；mammoth 的命令行参数解析依赖链存在 3 项 moderate 提示（sprintf-js / argparse / mammoth），本网站使用其文档解析 API，不将输入传递给 CLI 格式化器。未使用会降级 mammoth 的强制修复建议。

## 尚需真实环境验证

以下明确保留为上线/内容接入验收项，不标记为已经通过：

1. 用户自行部署后的 Netlify Database、Blobs、后台队列、定时备份和重部署持久性。
2. 独立外部备份接收端与至少 7 天保留策略。项目已实现发送接口，但未配置或声称已有独立副本。
3. 用户实际 DOCX 表格、多栏 PDF、长图与扫描资料的转换质量。目前测试资料为人工构造样本；复杂来源仍需人工校对。
4. 图片与扫描 PDF 自动 OCR。当前明确失败并支持人工整理，没有配置第三方识别服务。
5. 大规模内容/素材和并发负载；完整备份当前适合小站，累计文件多时需流式/增量升级。

原始 PRD 的 A01–A15 由上述验证覆盖核心流程；OCR 自动识别质量、真实样本、云端运行与独立备份条件尚未满足完整生产验收。
