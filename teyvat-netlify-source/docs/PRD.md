# 原神角色攻略网站需求文档

版本：V2.0（按用户反馈修订的解决方案）  
修订日期：2026-10-11  
阶段：需求与方案设计，尚未实施网站开发。

## 1. 项目定位与本次修订

建设一个可导入攻略资料、将资料整理为交互式角色攻略页面的网站。管理员提供攻略文件或粘贴信息，系统辅助提取、整理并映射到展示组件；玩家进入角色页面，直接查配装、配队、培养优先级和操作循环。

内容组织围绕“角色 → 玩法方案 → 可视化模块”，不以帖子列表、作者动态或长篇文章流作为核心入口。评论、评分和点赞作为攻略页的反馈区，不改变网站的攻略工具定位。

### 已确定需求

- 完整全栈系统，包含公开前台、管理后台、服务端接口、数据库和文件存储。
- 管理员可以导入攻略文件或信息，处理成方便前端查看的形式。
- 其他人可以浏览、评论、评分、点赞，但不能投稿攻略。
- 支持多位管理员；用户本人为唯一最高管理员，其他管理员仅具备发布相关权限。
- 发布管理员发布攻略不需要最高管理员审核。
- 本阶段先完成需求和解决方案，不直接开发或部署。

### 建议默认规则（尚未由用户指定）

- 浏览免登录；评论、评分、点赞需普通用户账号登录。
- 评分针对具体攻略方案的质量，采用 1～5 星，不是给游戏角色强度打分。
- 发布管理员可导入、编辑自己的未发布内容并直接发布；已发布内容的修改、下架、删除默认由最高管理员执行，严格对应“其他管理员只能发布”。
- 公开目录可包含尚无攻略的角色，显示“攻略待补充”，不再强制隐藏无攻略角色。
- 文件格式、识别能力和视觉效果按下文方案实现；具体解析工具、模型服务、登录渠道在技术设计阶段确定。

## 2. 角色与权限解决方案

| 操作 | 匿名访客 | 普通用户 | 发布管理员 | 最高管理员（站长） |
| --- | --- | --- | --- | --- |
| 阅读公开攻略、查看公开评论 | 可以 | 可以 | 可以 | 可以 |
| 评论、评分、点赞 | 登录后 | 可以 | 可以 | 可以 |
| 删除自己的评论、修改自己的评分、取消点赞 | 不可以 | 可以 | 可以 | 可以 |
| 创建攻略、上传源文件、整理草稿 | 不可以 | 不可以 | 仅自己的内容 | 全部 |
| 查看源文件、解析结果、私有预览 | 不可以 | 不可以 | 仅自己的内容 | 全部 |
| 发布新的攻略方案 | 不可以 | 不可以 | 直接发布，无需审核 | 直接发布 |
| 删除未发布草稿及其未引用素材 | 不可以 | 不可以 | 仅自己的内容 | 全部 |
| 修改、替换、下架或删除已发布内容 | 不可以 | 不可以 | 默认不允许 | 可以 |
| 管理角色目录、主推荐方案和首页推荐 | 不可以 | 不可以 | 不可以 | 可以 |
| 隐藏他人评论、处理举报、限制违规账号 | 不可以 | 不可以 | 不可以 | 可以 |
| 邀请、禁用发布管理员及调整权限 | 不可以 | 不可以 | 不可以 | 可以 |
| 修改全站设置、执行备份等系统操作 | 不可以 | 不可以 | 不可以 | 可以 |

发布管理员由最高管理员创建或邀请，不开放自行申请管理员权限。普通用户注册必须由服务端固定为普通用户，不能通过传递角色字段提升权限。最高管理员在初始化时创建，不允许通过普通后台操作删除或降级唯一最高管理员。

禁用发布管理员后立即撤销其会话和写入权限，已发布攻略默认保留，由最高管理员决定是否下架。

“无需审核”意味着没有待审核状态，也没有需要站长批准才能上线的环节。发布者自行预览、修正解析结果后即可发布；系统只做字段、格式、资源和权限校验。

若后续希望发布管理员能够更新自己的已发布方案，可增加这一独立权限；本版不默认扩大“仅发布”的范围。

## 3. 攻略导入与处理方案

### 3.1 输入方式

| 输入 | 处理方式 | 需要明确的边界 |
| --- | --- | --- |
| 粘贴文本、TXT、Markdown | 提取文本、段落、标题、列表和可识别表格 | 没有标题或结构混乱时允许人工指定模块 |
| Word（DOCX） | 提取段落、表格及内嵌图片 | 不承诺保留原文档全部排版；旧版 DOC 需先转换 |
| PDF | 优先读取文本层、表格和图片；扫描页通过 OCR 识别 | 多栏、合并表格和小字可能识别不准，需要提示并校对 |
| 攻略长图、截图（PNG/JPEG/WebP） | OCR 提取信息，关联原图以供对照 | 原图可放大查看；识别失败时仍可手动建立展示模块 |

首版不把任意网址抓取作为输入，不要求用户把资料预先改写成规定模板。图片、扫描 PDF 的自动转换依赖选定的 OCR 能力，不能仅上传一张图片就宣称完成了结构化整理。

### 3.2 处理流程

上传文件或粘贴信息 → 提取内容 → 识别所属角色与玩法 → 整理为结构化模块 → 标注缺失/歧义/冲突 → 发布者校对预览 → 直接发布。

1. 选择角色，可根据输入识别并推荐候选，存在歧义时由发布者选择。角色目录由最高管理员维护。
2. 创建导入任务并保留原始资料。任务显示排队、处理中、待校对、失败等状态；失败支持重试。
3. 解析文字、表格和内嵌图片，记录来源位置，如 PDF 页码、文档段落或原始图片。
4. 使用规则和可选的模型辅助能力，将信息映射为定位、配装、词条、天赋、配队、循环等模块。
5. 模型辅助仅整理输入中已有信息，不擅自补全数值、推荐理由、武器排序或当前游戏版本。缺失项留空；无法归类的段落进入“待整理内容”，不得静默丢弃。
6. 后台左侧展示原文/原图，右侧展示将要发布的卡片。发布者可以修改字段、合并拆分卡片、拖动排序、隐藏不适用模块及补充素材。
7. 系统提供重复方案和内容冲突提示。导入新文件不能自动覆盖线上方案，也不能修改其他管理员的内容。
8. 发布时生成符合统一结构约束的攻略数据，由前端组件渲染，不直接执行源文件中的 HTML 或脚本。

整份文件包含多个角色或多种玩法时，先拆分为候选方案，逐个确认角色和展示结构；首版不支持未经确认的一键批量上线。上传后至少提供“完整结构化”“部分待整理”“无法识别”三种结果提示，不承诺任意资料都可完全自动转换。

### 3.3 信息准确性与发布条件

- 解析生成的数据可以编辑，原始文件保持不变并与导入任务关联。
- 涉及武器、圣遗物、角色别名的匹配出现歧义时保留原名称，不直接替换为猜测对象。
- 推荐百分比、伤害数值、充能需求等必须附带来源已有的条件；来源未提供时显示“条件未注明”，不能生成看似精确的对比图。
- 发布必填：所属角色、方案名称、适用游戏版本说明（可明确填“来源未注明”）、至少一个有效攻略模块。来源位置与未解决问题保存在管理端。
- 阻止发布：文件仍在处理、角色未选择、数据结构无效、关联素材不可用、权限不符。
- 缺少个别模块可发布；页面隐藏缺失模块或注明待补充，不生成空卡片墙。
- 发布者查看问题清单并确认发布属于自身内容确认，不是额外审核流程。

## 4. 攻略前端形式：角色攻略工作台

本部分替换 V1 的“固定字段 + 长正文”方案。一个角色对应一个稳定入口，页面顶部选择玩法方案，下面的卡片随方案切换。原始资料用于溯源和补充，主要信息通过可视化模块查看。

### 4.1 角色页面布局

| 区域 | 展示形式 | 玩家可以做什么 |
| --- | --- | --- |
| 角色首屏 | 立绘/封面、元素、武器类型、定位标签、适用版本和一句话培养结论 | 快速了解角色用途和攻略适用范围 |
| 玩法方案切换 | 页签或下拉列表，例如“输出方案”“辅助方案”“低成本方案”；以实际导入内容为准 | 切换时同步更新装备、词条、队伍和循环，不混用不同方案的结论 |
| 快速配装 | 武器卡、圣遗物套装卡、主词条槽位和天赋优先级 | 首屏附近即可查看一套完整培养建议 |
| 武器对比 | 带图片、适用条件、优缺点的推荐卡；推荐顺序来自资料或管理员调整 | 选择至多 3 项并排比较；手机纵向比较 |
| 圣遗物与词条 | 套装组合卡、“时之沙/空之杯/理之冠”槽位卡、副词条优先级标签 | 展开替代搭配、适用条件和原因 |
| 配队方案 | 四个角色头像组成阵容卡，展示职责与队伍说明 | 点击位置查看来源提供的替代角色；没有完整替代方案时不自动重算结论 |
| 操作循环 | 角色头像、技能图标、步骤编号和说明组成的顺序时间线 | 逐步展开操作细节；无时长数据时不画虚构时间刻度 |
| 培养路线 | 天赋优先级、关键命座、材料清单和阶段目标卡 | 勾选材料准备进度，首版保存在当前浏览器，可重置，不改变攻略本身 |
| 机制细节 | 折叠说明、提示卡和带条件的表格 | 按需展开，避免首页被大段文字占满 |
| 来源与补充 | 原图放大查看、来源署名、内容更新说明 | 核对资料；原文件默认不公开下载 |
| 用户反馈 | 方案评分、点赞、评论区 | 交流当前方案，查看其他玩家反馈 |

页面示意：

角色立绘 + 名称 + 定位 + 版本

[方案 A] [方案 B] [方案 C]

[推荐武器] [圣遗物套装] [主词条] [天赋优先级]

[四人配队卡] → [角色 1 操作] → [角色 2 操作] → [输出阶段]

[替代方案与详细解释（展开）]

[评分与点赞] [评论区]

具体页签和卡片名称来自导入内容，示意名称不代表必须给每个角色制作相同玩法。

### 4.2 交互与视觉原则

- 采用角色主题视觉、元素配色、图标和卡片分区，让信息容易定位；动效只用于切换反馈，不干扰阅读。
- 页面有固定模块导航，允许直接分享某个角色、方案和模块的链接。
- 手机以纵向卡片和可折叠模块展示，桌面允许配装并排比较；无需依赖悬停才能读取关键解释。
- 切换方案时同步切换反馈区，评分和评论不会挂到错误方案上。
- 首版不进行自动伤害模拟。切换武器、配队时只展示已有资料支持的变化，不伪装成实时计算。
- 缺少图片时使用文字卡片或占位图，不阻止有效攻略发布。

### 4.3 角色目录与方案组织

取消“必须有一篇已发布攻略才展示角色”的条件。最高管理员可将角色目录中的角色设为公开或隐藏，公开角色即使没有攻略，也可展示基础资料和“攻略待补充”。玩家可勾选“只看已有攻略”。

角色页展示该角色已发布的玩法方案，不展示帖子流。新管理员发布的方案会立即出现在对应角色的方案选择器中，不需要站长再选择推荐才能被访问。站长可以指定默认推荐方案；未指定时默认使用最早发布且仍有效的方案，避免新增内容不断替换入口。

同一角色允许不同发布者提供不同方案，展示方案名称、维护者和适用版本，避免把相互冲突的来源强行合成一套攻略。相同名称提示重命名，不覆盖原方案。

## 5. 评论、评分与点赞解决方案

### 5.1 账号与入口

浏览攻略及公开评论无需登录。建议普通用户注册/登录后才能参与互动，以实现自己的评论管理、评分修改和点赞去重。具体采用邮箱验证还是第三方登录，在技术选型时确定；手机号不是默认必填项。

普通用户的写入权限仅限互动接口，不开放攻略导入、攻略编辑、文件上传或发布入口。管理员同时拥有普通用户互动能力。

### 5.2 评论

- 评论归属具体方案，记录发言时的攻略版本；支持文字评论和一层回复，首版不支持图片或附件。
- 默认发布后直接显示，不设逐条人工预审；提供基础频率限制、重复内容拦截和用户举报。
- 用户可以删除自己的评论；最高管理员可以隐藏或删除违规评论、处理举报、限制账号互动。
- 采用分页加载与时间排序。评论删除后若有回复，保留“该评论已删除”的占位，避免回复关系断裂。
- 评论区放在攻略主体之后，可折叠，避免抢占查攻略的入口。

### 5.3 评分

- 文案明确为“这份攻略对你有帮助吗”，1～5 星评价具体方案的质量。
- 每个账号对每个方案当前公开版本仅有一条有效评分，可以修改或撤销，不重复累加。
- 展示平均分和评分人数；无人评分显示“暂无评分”，不能显示为零分。较少评分时同时显示人数，避免误导。
- 攻略重新发布形成新版本后，当前评分重新统计；旧评分保留为历史数据，不混入新版均分。

### 5.4 点赞

- 每个账号对同一方案最多一次点赞，重复点击可取消。
- 点赞绑定方案本身，攻略更新保留点赞；文案显示为累计点赞，避免与当前版本评分混淆。
- 数据库唯一约束和幂等接口防止并发重复计数，页面刷新后保持状态。
- 最高管理员可处置滥用账号；账号去重与频率限制只能降低刷量，不承诺完全消除多账号刷量。

方案下架后停止新增评论、评分和点赞，公开入口不再展示其内容与互动；保留数据供站长管理。只剩无攻略的公开角色时，显示待补充状态。

## 6. 后台页面与发布流程

| 后台页面 | 发布管理员 | 最高管理员 |
| --- | --- | --- |
| 工作台 | 自己的导入任务、待整理方案和发布记录 | 全站内容、导入异常、用户举报概况 |
| 攻略导入 | 上传自己的资料或粘贴信息 | 同左，可查看全站任务 |
| 可视化整理器 | 原文对照、字段修改、卡片排序及预览 | 同左，可管理全部内容 |
| 攻略管理 | 查看自己的方案、维护自己的草稿、发布新方案 | 更新、替换、推荐、下架和删除全站方案 |
| 角色与素材库 | 选择已有角色和可用公共素材，管理自己的私有草稿素材 | 管理角色目录、共享素材及全部引用关系 |
| 评论与举报 | 仅自己的普通用户互动操作 | 全站处置 |
| 账号和站点设置 | 修改自己的密码和退出登录 | 管理用户、发布管理员、推荐和站点配置 |

发布状态为草稿、已发布、已下架，不设置“待审核”。解析任务状态与发布状态分开，解析成功不等于自动发布。

更新已发布方案时使用独立工作副本，只有最高管理员点击更新发布后才替换公开版本。保留历史公开版本及操作记录，用于溯源、评论版本标记和评分统计；首版不必提供版本对比及一键回滚界面。

服务端检测修订冲突与重复发布请求；发布需要原子切换公开版本、图片可见性和相关索引。失败时保留草稿，不能出现只有半套卡片更新的页面。内容下架后失效缓存、移除公开方案入口，并在原方案 URL 返回 404；角色目录是否继续显示由角色公开状态决定。

## 7. 全栈数据与服务边界

### 7.1 核心数据

| 数据对象 | 用途 |
| --- | --- |
| 用户与会话 | 普通用户、发布管理员、最高管理员，账号状态及会话撤销 |
| 角色目录 | 名称、别名、元素、武器类型、头像、立绘和公开状态 |
| 攻略方案 | 所属角色、方案名称、发布者、状态和公开版本引用 |
| 攻略版本 | 带结构版本号的模块数据、顺序、适用版本说明、来源、发布时间 |
| 原始资料与导入任务 | 私有原文件、解析状态、错误信息、结构化结果和来源位置 |
| 素材及引用 | 图片类型、存储位置、所属者、来源与公开/私有引用 |
| 评论与举报 | 方案、发言时版本、作者、回复关系、可见状态和举报处理结果 |
| 评分 | 用户、方案版本、星数；用户与版本组合唯一 |
| 点赞 | 用户、方案；用户与方案组合唯一 |
| 站点设置与日志 | 推荐方案、站点信息、账号及内容变更记录 |

攻略结构采用可校验的组件数据，例如“装备卡、词条组、队伍卡、操作步骤、说明块”。前端按组件类型渲染，不允许资料或模型输出任意脚本。模型输出也必须经过结构校验与服务端输入清洗。

### 7.2 接口分层

- 公开读取：角色目录、已发布方案、公开评论、评分和点赞汇总。
- 用户互动：自己的评论、评分、点赞及举报，需登录且只操作自己的记录。
- 发布管理：自己的导入任务、原资料、草稿预览和首次发布，需发布权限及对象归属校验。
- 站长管理：全站内容、账号、角色目录、推荐与互动处置，需最高管理员权限。

不仅按接口校验角色，还要校验对象归属。猜测其他管理员的文件地址、草稿编号或改写请求中的所属者，不能访问或覆盖他人私有内容。

### 7.3 部署构成

系统包含网页应用、服务端、关系型数据库、持久化文件存储与异步导入处理任务。OCR/模型整理能力作为可替换模块；服务不可用时保留源文件，允许重试或手动整理。

技术栈、模型/OCR供应商及运行位置留到技术方案阶段确定。若需要把文件发送给外部服务，应在后台导入入口明确说明；不得默认把管理员资料发送到未配置的第三方。导入文件大小、页数和处理超时设置上限，具体值通过代表性样本测试后确定。

## 8. 文件、安全、体验和运维要求

- 原文件默认保持私有；公开的只是确认发布的模块和展示图片。原文件公开下载属于后续独立配置，不与发布动作自动绑定。
- 上传检查实际格式、体积和解压后的资源总量；文档宏、脚本、外部链接引用不执行、不自动请求。
- 文件解析在有资源限制的独立任务中完成，支持失败状态、重试、重复任务去重及任务超时。
- 草稿及其专用图片需要鉴权，发布后仅公开被发布版本引用的展示资源；下架时撤销无其他公开引用资源的公开访问并清理缓存。已下载副本无法撤回。
- 有效草稿、当前或保留历史版本引用的素材不能直接删除；已发布图片不能由普通发布管理员通过替换源文件间接修改。
- 密码安全哈希存储；会话使用安全 Cookie；登录和互动操作限频，写操作具备 CSRF 防护。禁用账号后会话即时失效。
- 使用数据库约束、事务和参数化查询；评论、链接、解析结果及预览均进行输入清洗。
- 在 360 px、768 px、1440 px 宽度验证页面，关键操作支持键盘与可见焦点；图片有替代文本。
- 角色与方案链接稳定，分享链接可定位方案/模块；公开页面提供可索引内容。私有预览须鉴权，不能仅靠禁止索引保护。
- 数据库、原文件和展示图片使用持久化存储；每日备份，至少保留最近 7 天且有独立副本，交付前验证一次恢复。
- 列表、评论分页，图片缩略和延迟加载，复杂解析不阻塞网页请求。公开内容变化目标在 10 秒内可由新请求看到，具体性能指标在部署方案中落实。

## 9. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 导入攻略信息 | 文本、DOCX、文本 PDF、扫描 PDF 和图片样本均走对应流程，展示结果或明确失败原因 |
| A02 | 结构化转换 | 代表性样本的装备、词条、配队和操作步骤转为对应组件；未识别内容进入待整理区 |
| A03 | 原文对照与准确性 | 模块可回看来源；缺失数据不被编造；发布者可校正并预览最终布局 |
| A04 | 非帖子式展示 | 从角色目录直接进入角色工作台，切换方案联动所有模块，配装对比和循环展示可用 |
| A05 | 无攻略角色 | 公开角色可显示“攻略待补充”；“只看已有攻略”筛选正确 |
| A06 | 直接发布 | 发布管理员通过系统校验后立即上线，不存在站长审批步骤，新方案立即可选 |
| A07 | 权限隔离 | 普通用户不能投稿；发布管理员不能访问他人草稿、变更账号或修改/下架已发布方案 |
| A08 | 最高管理员 | 可管理全站内容、账号、角色目录、推荐及违规互动；禁用管理员后其写入立即失败 |
| A09 | 评论 | 登录后评论与回复正常、自己可删除、他人不能删除，站长可隐藏，举报可处理 |
| A10 | 评分 | 同一用户对同一版本仅一条有效评分，修改与撤销正确；新版统计与旧版分离 |
| A11 | 点赞 | 重复及并发请求不重复计数，取消后计数正确，刷新保留状态 |
| A12 | 草稿和源文件私有 | 公开查询和猜测 URL 均不能读取草稿、原文件或草稿图片 |
| A13 | 更新与下架 | 草稿不影响线上；站长更新原子生效；下架后原方案无法公开读取或新增互动 |
| A14 | 异常与冲突 | OCR/模型失败可重试或手动整理；过期保存提示冲突，不静默覆盖内容 |
| A15 | 持久化和体验 | 重启后内容、互动和素材仍在；备份可恢复；手机与桌面主要操作完整可用 |

验收需使用实际代表性攻略样本：至少一份表格文档、一份文字 PDF、一份扫描或长图资料、一份结构混乱文本，以及包含歧义/缺失数据的样本。先评估转换质量，再扩大格式和自动化范围；不能只用预制结构化数据演示导入成功。

## 10. 实施顺序与交付物

1. 用真实攻略样本验证提取与结构化方案，同时制作角色工作台原型，确认卡片阅读效果。
2. 建立账号、最高管理员/发布管理员/普通用户权限、角色目录和私有文件存储。
3. 完成导入任务、原文对照整理器、预览、无审核发布及站长内容管理。
4. 完成角色目录、玩法切换、配装对比、队伍与循环组件及移动端适配。
5. 完成评论、评分、点赞、举报与站长处置，再进行权限、异常和恢复验证。

最终交付源代码、数据库迁移、部署与备份说明、管理员操作说明、导入能力及限制说明、验收记录。本阶段交付本需求与解决方案文档，不承诺未经验证的识别准确率、工期或模型调用成本。

## 11. 首版边界及待落实事项

首版不包含公众攻略投稿、帖子动态流、私信论坛、管理员发布审核、自动采集外部网站、自动伤害模拟、游戏账号绑定、付费阅读、多语言或原生移动应用。

开发前需要落实的事项：

| 事项 | 当前方案 |
| --- | --- |
| 实际攻略文件样本 | 用于验证格式、模块拆分和 OCR 难点；不阻碍本次需求方案完成 |
| 发布管理员的发布后权限 | 默认只能首次发布；已发布内容由最高管理员更新和下架 |
| 普通用户登录方式 | 建议登录后互动，渠道待技术方案确定 |
| 攻略页视觉 | 角色主题视觉 + 可切换方案 + 配装/队伍/循环卡片，通过原型细化 |
| 解析服务与预算 | OCR/模型可替换，文件发送位置和成本在选型时明确 |
| 站点名称、域名、服务器 | 待定；不提前购买服务或上线 |
